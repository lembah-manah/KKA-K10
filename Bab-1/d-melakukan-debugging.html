Bab 1 · Bagian D

Melakukan Debugging

Ringkasan Bagian

Bagian ini menjelaskan pengertian debugging beserta asal-usul istilah "bug", tiga jenis kesalahan program (syntax error, runtime error, logic error) lengkap dengan contohnya, serta lima strategi praktis untuk menemukan dan memperbaiki kesalahan — mulai dari membaca pesan error hingga rubber duck debugging. Ditutup dengan contoh kasus nyata memperbaiki logic error pada perhitungan rata-rata.

1. Apa Itu Debugging?

Debugging adalah proses menemukan dan memperbaiki kesalahan (bug) dalam suatu program. Istilah "bug" (serangga) berasal dari kisah nyata pada tahun 1947, ketika seekor ngengat ditemukan tersangkut di dalam relai komputer Harvard Mark II sehingga menyebabkan program tidak berjalan dengan benar. Sejak saat itu, istilah bug melekat untuk menyebut kesalahan dalam program, dan debugging adalah keterampilan wajib bagi setiap programmer — bahkan programmer profesional menghabiskan sebagian besar waktunya untuk melakukan debugging, bukan hanya menulis kode baru.

2. Jenis-Jenis Kesalahan (Error)

Jenis ErrorPenyebabContoh
Syntax Error
(Kesalahan Penulisan)		 Penulisan kode tidak sesuai aturan tata bahasa pemrograman. print("Halo" → tanda kurung tutup tidak ditulis
Runtime Error
(Kesalahan Saat Dijalankan)		 Kode benar secara tata bahasa, tetapi gagal saat dijalankan karena kondisi tertentu. 10 / 0 → pembagian dengan angka nol
Logic Error
(Kesalahan Logika)		 Program berjalan lancar tanpa pesan error, tetapi hasilnya tidak sesuai harapan. Rumus rata-rata tertulis (a+b) * 2 padahal seharusnya (a+b) / 2

3. Strategi dan Teknik Debugging

  1. Membaca pesan error dengan teliti — Python biasanya menunjukkan baris dan jenis kesalahan secara spesifik pada pesan traceback.
  2. Menelusuri kode baris demi baris (tracing) — jalankan program secara manual di atas kertas atau menggunakan print() untuk memeriksa nilai variabel di setiap tahap.
  3. Menggunakan print() sebagai alat bantu — sisipkan perintah print() di titik-titik penting untuk melihat nilai variabel saat program berjalan.
  4. Membagi program menjadi bagian kecil (isolasi masalah) — uji setiap fungsi secara terpisah untuk menemukan bagian mana yang bermasalah.
  5. Meminta bantuan rekan (rubber duck debugging) — coba jelaskan kode milikmu baris demi baris kepada teman atau bahkan kepada benda mati; sering kali proses menjelaskan itu sendiri membantu menemukan kesalahan.

Contoh Kasus Debugging

Perhatikan program berikut yang seharusnya menghitung rata-rata tiga nilai ulangan, namun menghasilkan output yang salah:

# Kode bermasalah
nilai1 = 80
nilai2 = 90
nilai3 = 70
rata_rata = nilai1 + nilai2 + nilai3 / 3
print(f"Rata-rata: {rata_rata}")  # Output salah: 193.33

Kesalahan di atas termasuk logic error, karena operator pembagian (/) hanya berlaku untuk nilai3 akibat urutan operasi matematika (pembagian dan perkalian dikerjakan lebih dahulu daripada penjumlahan). Perbaikannya adalah dengan menambahkan tanda kurung agar penjumlahan dilakukan lebih dahulu:

# Kode setelah diperbaiki
rata_rata = (nilai1 + nilai2 + nilai3) / 3
print(f"Rata-rata: {rata_rata}")  # Output benar: 80.0

Mengapa Debugging Penting untuk AI?

Dalam pengembangan sistem AI, kesalahan logika sekecil apa pun pada tahap pemrosesan data dapat menyebabkan model AI memberikan prediksi yang keliru dalam skala besar. Oleh karena itu, kebiasaan teliti dan sistematis dalam debugging yang dilatih sekarang akan menjadi keterampilan yang sangat berharga ketika kelak mengembangkan proyek berbasis AI.
